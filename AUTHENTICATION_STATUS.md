# 🔐 Статус авторизации в проекте

## ❌ Текущее состояние: Авторизация НЕ реализована

### Что работает сейчас:

1. **История отчётов доступна ВСЕМ** (без авторизации)
   - Любой пользователь может видеть все отчёты через `/api/reports`
   - Нет фильтрации по пользователю
   - Нет проверки авторизации

2. **Отчёты сохраняются без привязки к пользователю**
   - Поле `userId` в таблице `Report` опциональное (`String?`)
   - При сохранении `userId` остаётся `null`
   - Все отчёты видны всем

3. **Страница `/reports` показывает заглушку**
   - Сообщение: "Функция в разработке"
   - Текст: "Авторизуйтесь, чтобы сохранять историю анализов"
   - Но на самом деле история уже работает через API

## ✅ Что планируется (в будущем):

### 1. Реализация NextAuth.js

- Авторизация через OAuth (Google, GitHub и т.д.)
- Email/password авторизация

### 2. Привязка отчётов к пользователям

- При сохранении отчёта будет записываться `userId`
- Фильтрация отчётов по пользователю
- Каждый пользователь видит только свои отчёты

### 3. Обновление API endpoints

```typescript
// Будет раскомментировано:
const session = await getServerSession();
if (!session?.user) {
  return NextResponse.json(
    { error: "Требуется авторизация" },
    { status: 401 }
  );
}

const reports = await prisma.report.findMany({
  where: { userId: session.user.id }, // Только отчёты пользователя
  orderBy: { createdAt: "desc" },
});
```

## 📋 Что нужно сделать для добавления авторизации:

### Шаг 1: Установить NextAuth.js

```bash
npm install next-auth@beta
```

### Шаг 2: Настроить провайдеры

- Создать файл `app/api/auth/[...nextauth]/route.ts`
- Настроить OAuth провайдеры (Google, GitHub)
- Настроить адаптер для Prisma

### Шаг 3: Обновить API endpoints

- Раскомментировать проверку авторизации в `/api/reports`
- Добавить проверку в `/api/analyze` (для сохранения userId)
- Добавить проверку в `/api/analysis/[id]`

### Шаг 4: Обновить UI

- Добавить кнопку "Войти" в Header
- Показывать имя пользователя
- Обновить страницу `/reports` для работы с авторизацией

### Шаг 5: Обновить RLS политики

- В Supabase создать политики для фильтрации по userId
- Ограничить доступ к чужим отчётам
