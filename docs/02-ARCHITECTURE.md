# 🏗️ Архитектура и принципы работы

## Общая архитектура

Приложение построено на Next.js 14 с использованием App Router. Анализ данных выполняется полностью на стороне сервера (API Routes), результаты сохраняются в Zustand store и отображаются на клиенте.

## Поток данных от загрузки до отображения

### 1. Загрузка файла

**Файл:** `app/page.tsx`

Пользователь загружает один или несколько Excel файлов через drag-and-drop интерфейс:

```typescript
// Состояние хранится в Zustand store
const { mainFile, costFile, setMainFile, setCostFile } = useUploadStore();
```

**Особенности:**
- Поддержка множественных файлов (объединение отчётов)
- Опциональный файл себестоимости
- Валидация формата (.xls, .xlsx)
- Разбиение на чанки для больших файлов (макс. 4.5 МБ на чанк)

### 2. Отправка на анализ

**Файл:** `app/page.tsx` → `POST /api/analyze`

Файлы отправляются на сервер через FormData:

```typescript
const formData = new FormData();
files.forEach(file => formData.append("files", file));
if (costFile) formData.append("costFile", costFile);
formData.append("analysisId", analysisId);

const response = await fetch("/api/analyze", {
  method: "POST",
  body: formData,
});
```

### 3. Парсинг файла

**Файл:** `app/api/analyze/route.ts` → `lib/analysis/parsers/file-parser.ts`

#### Этапы парсинга:

1. **Определение формата** (XLS или XLSX)
2. **Чтение сырых данных** из Excel файла
3. **Декодирование кодировок:**
   - KOI-7 (специфичная кодировка Ozon)
   - UTF-16LE (кириллица в старых файлах)
4. **Извлечение строк** из таблицы
5. **Парсинг данных:**
   - ID начисления
   - Номер заказа
   - SKU товара
   - Тип начисления
   - Суммы и даты

**Результат:** Массив `ChargeRow[]` - строк начислений

### 4. Агрегация заказов

**Файл:** `lib/analysis/aggregators/order-aggregator.ts`

#### Логика агрегации:

1. **Извлечение номера заказа** из ID начисления
   - Паттерн: `ORDER_NUMBER-SKU-CHARGE_ID`
   - Берём часть до второго дефиса

2. **Группировка строк** по номеру заказа

3. **Объединение заказов** с одинаковым `orderNumber+sku` (заказы, разбитые по периодам)

4. **Расчёт итогов по заказу:**
   - Сумма итого (суммирование всех начислений)
   - Статус заказа (completed, returned, partial_return, cancelled)
   - Даты (принятия, отгрузки, доставки)
   - SKU и название товара

5. **Определение типа заказа:**
   - Обычный заказ
   - Возврат (по типу начисления "Возврат выручки")
   - Частичный возврат

**Результат:** Массив `AggregatedOrder[]` - агрегированных заказов

### 5. Добавление себестоимости

**Файл:** `lib/analysis/calculators/cost-calculator.ts`

Если загружен файл себестоимости:

1. Парсинг файла себестоимости (`lib/analysis/cost-parser.ts`)
2. Сопоставление по SKU/артикулу
3. Добавление поля `cost` к заказам
4. Расчёт прибыли: `profit = revenue - cost - fees`

**Результат:** Заказы с заполненной себестоимостью

### 6. Расчёт метрик

#### 6.1. Метрики по товарам

**Файл:** `lib/analysis/calculators/product-metrics-calculator.ts`

Для каждого уникального SKU:
- Общая выручка
- Количество заказов
- Средняя цена
- Процент возвратов
- Прибыль (если есть себестоимость)
- Маржа

**Результат:** Массив `ProductMetrics[]`

#### 6.2. Сводные метрики

**Файл:** `lib/analysis/calculators/summary-calculator.ts`

- Общая выручка (gross revenue)
- Чистая выручка (net revenue = gross - возвраты)
- Чистая прибыль (net profit)
- Количество заказов (уникальных)
- Средний чек
- Процент возвратов
- Процент отмен
- Комиссии Ozon
- Маржинальность

**Результат:** Объект `Summary`

#### 6.3. Разбивка затрат

**Файл:** `lib/analysis/calculators/summary-calculator.ts`

Группировка затрат по категориям:
- Комиссия Ozon
- Логистика
- Обработка заказов
- Эквайринг
- Хранение
- Реклама
- Штрафы/Возвраты
- Прочее

**Результат:** Массив `CostBreakdown[]`

#### 6.4. Метрики по дням

**Файл:** `lib/analysis/calculators/daily-metrics-calculator.ts`

Группировка заказов по дням:
- Выручка по дням
- Количество заказов
- Прибыль

**Результат:** Массив `DailyMetrics[]`

#### 6.5. Детализация по типам начислений

**Файл:** `lib/analysis/calculators/charge-type-breakdown-calculator.ts`

Группировка всех начислений по типам:
- Группы типов (Выручка, Комиссии, Логистика и т.д.)
- Детализация по каждому типу
- Суммы и количество

**Результат:** Массив `ChargeTypeBreakdown[]`

### 7. Выявление проблемных зон

**Файл:** `lib/analysis/analyzers/problem-identifier.ts`

Анализ данных на предмет проблем:
- Товары с высоким процентом возвратов
- Убыточные товары
- Низкая маржинальность
- Высокие комиссии

**Результат:** Массив `ProblemArea[]`

### 8. Генерация рекомендаций

**Файл:** `lib/analysis/analyzers/recommendation-generator.ts`

Генерация рекомендаций на основе:
- Проблемных зон
- Сводных метрик
- Топ товаров

**Результат:** Массив `Recommendation[]`

### 9. Сохранение результата

**Файл:** `lib/store/analysis-store.ts`

Результат анализа сохраняется в Zustand store:

```typescript
setAnalysisResult({
  id: analysisId,
  fileName: fileName,
  summary: summary,
  // ... другие данные
});
```

### 10. Отображение

**Файл:** `app/analysis/[id]/page.tsx`

Страница результатов отображает:
- Сводные метрики (карточки)
- Графики (Recharts)
- Таблицы товаров
- Рекомендации
- Кнопки экспорта

## Исключение товаров

### Механизм работы

1. Пользователь выбирает товары для исключения (по SKU)
2. Состояние исключений хранится в `analysisStore.excludedSkus` (Set<string>)
3. При пересчёте:
   - Фильтрация заказов по SKU
   - Пересчёт всех метрик
   - Обновление результата

**Файл:** `lib/analysis/utils/recalculate-with-exclusions.ts`

### Пересчёт метрик

При исключении товаров пересчитываются:
- Summary (сводные метрики)
- CostBreakdown (разбивка затрат)
- DailyMetrics (метрики по дням)
- ProfitTrends (тренды прибыли)
- ChargeTypeBreakdown (детализация по типам)
- CostReports (отчёты по себестоимости)

## Объединение результатов нескольких файлов

**Файл:** `app/page.tsx` → `mergeFrontendResults()`

При загрузке нескольких файлов:
1. Каждый файл обрабатывается отдельно
2. Результаты объединяются:
   - Суммирование метрик (выручка, прибыль, заказы)
   - Объединение массивов (товары, заказы)
   - Расчёт средних значений
   - Объединение периодов

## AI анализ

**Файл:** `app/api/ai/route.ts`

AI анализ выполняется отдельно по запросу:

1. Подготовка контекста (`lib/ai/context-preparer.ts`)
2. Выбор провайдера (OpenAI, Anthropic, Google)
3. Отправка запроса с данными анализа
4. Получение и сохранение рекомендаций

## Оптимизации производительности

### 1. Ленивая загрузка компонентов

```typescript
const ChartSection = dynamic(() => import("@/components/report/ChartSection"));
```

### 2. Мемоизация вычислений

Использование `useMemo` для тяжёлых вычислений в компонентах.

### 3. Разбиение на чанки

Большие файлы разбиваются на чанки для обработки.

### 4. Кэширование результатов

Результаты анализа сохраняются в store и не пересчитываются при перерисовке.

## Обработка ошибок

1. **Валидация файлов** - проверка формата и размера
2. **Try-catch блоки** - обработка ошибок парсинга
3. **Логирование** - запись ошибок в лог
4. **Пользовательские сообщения** - понятные сообщения об ошибках

## Расширяемость

Архитектура позволяет легко добавлять:
- Новые калькуляторы метрик
- Новые анализаторы
- Новые типы визуализации
- Новые форматы экспорта
